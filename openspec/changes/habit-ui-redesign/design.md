## Context

当前应用是基于 React + Vite 的习惯打卡 PWA，采用暗色系 UI（深蓝/深灰基调），布局为纵向列表，底部有3个 Tab（习惯打卡、待办计划、Todo）。习惯只能新增不能编辑或删除，打卡无明显正向反馈动效。

目标用户为 25-30 岁年轻女性，当前的开发者风格 UI 不符合该群体的审美偏好。需要全面重设计交互和视觉，转向白色基底 + 多巴胺色系的简洁可爱风格。

## Goals / Non-Goals

**Goals:**
- 将整体 UI 从暗色系切换为白色基底 + 多巴胺色系（明亮粉、薄荷绿、柠檬黄、薰衣草紫、珊瑚橙等）
- 习惯页改为 2 列方块网格布局，新增习惯以末尾"+"方块呈现
- 习惯支持编辑和删除操作
- 新增习惯详情页（时间轴展示打卡记录）
- 打卡时触发全屏撒花动效
- 精简底部导航（移除待办计划和 Todo），保留 Tab 栏供扩展
- 保持 PWA、Garfish 子应用兼容性不变

**Non-Goals:**
- 不改变数据存储机制（仍用 Local Storage）
- 不删除待办计划和 Todo 的代码/路由（仅从导航中隐藏）
- 不实现深色/浅色主题切换
- 不改变打卡记录的数据结构

## Decisions

### 决策 1：多巴胺色系色板定义

**选择**: 定义一套明确的多巴胺色系 CSS 变量作为全局设计 Token

```
--color-pink:      #FF6B9D    /* 明亮粉 */
--color-mint:      #5ECFB1    /* 薄荷绿 */
--color-lemon:     #FFD93D    /* 柠檬黄 */
--color-lavender:  #B39DDB    /* 薰衣草紫 */
--color-coral:     #FF8A65    /* 珊瑚橙 */
--color-sky:       #64B5F6    /* 天空蓝 */
--color-peach:     #FFAB91    /* 蜜桃色 */
--color-lilac:     #CE93D8    /* 丁香紫 */
```

背景为纯白 `#FFFFFF`，文字主色 `#2D2D2D`，次级文字 `#8E8E93`，卡片背景 `#FAFAFA`。

**理由**: 多巴胺色系的核心在于高饱和度但不刺眼的中等明度色彩。以白色为底可以让彩色模块更突出，同时保持整洁不杂乱。

**替代方案**:
- 使用奶油色/米色基底：温馨但与多巴胺的鲜明感冲突
- 使用渐变背景：容易视觉疲劳，不符合简洁要求

### 决策 2：习惯卡片方块网格布局

**选择**: CSS Grid 2列等宽布局，每个习惯卡片为正方形或近正方形

布局结构：
```
[习惯A] [习惯B]
[习惯C] [  +  ]    ← 新增卡片始终在末尾
```

每个方块内展示：习惯名称、寄语（缩略）、累计天数、打卡按钮。方块背景使用习惯的自选颜色（浅色调 + 白色文字/深色文字自适应）。

**理由**: 方块网格在移动端空间利用率高，视觉上更活泼有趣，与多巴胺色系配合良好。末尾的"+"卡片保持一致的视觉节奏。

### 决策 3：撒花动效实现 — canvas-confetti

**选择**: 使用 `canvas-confetti` npm 库实现全屏撒花动效

**理由**: `canvas-confetti` 仅约 6KB gzipped，API 简单（一行调用），性能好（基于 Canvas），效果美观。相比自行实现 CSS 动画，开发成本低且效果更丰富。

**替代方案**:
- 纯 CSS 动画：可控性差，粒子数量有限，效果单一
- 自行实现 Canvas 粒子系统：工作量大，收益有限

### 决策 4：时间轴展示打卡记录

**选择**: 新增 `/habit/:id` 路由，以垂直时间轴（从上到下，最近日期在前）展示该习惯的打卡历史

时间轴每个节点：
- 日期（YYYY-MM-DD）
- 习惯颜色圆点
- 简单的连接线

**理由**: 时间轴是展示时间序列数据最直观的方式，垂直方向适合移动端滚动浏览，实现简单无需额外依赖。

### 决策 5：习惯编辑与删除交互

**选择**: 长按或点击习惯卡片右上角"⋯"菜单触发编辑/删除操作

- 编辑：复用 HabitForm 组件，预填现有数据
- 删除：弹出确认对话框后执行

**理由**: 右上角菜单是移动端常见的卡片操作模式，不干扰打卡主流程。编辑复用表单组件减少代码量。

### 决策 6：底部导航精简策略

**选择**: 只在 BottomNav 中保留"习惯打卡"一个 Tab，但保留 Tab 栏的基础结构和样式。路由配置中保留 /planner 和 /todo 路径但不在导航中暴露。

**理由**: 保持扩展性——未来新增功能只需在 BottomNav tabs 数组中添加条目即可。不删除路由可避免已有 URL 书签失效。

## Risks / Trade-offs

- **[白色基底对比度]** → 确保文字颜色与白色背景对比度达到 WCAG AA 标准（4.5:1）。多巴胺色系作为背景色时使用浅色调（加白 85%），文字保持深色。
- **[canvas-confetti 新依赖]** → 增加约 6KB 包体积。**缓解**: 相对于视觉体验提升，完全可接受。可做按需加载（dynamic import）。
- **[习惯卡片方块空间有限]** → 长名称和长寄语可能溢出。**缓解**: 名称限制显示 1 行，寄语限制 1 行，溢出截断加省略号。
- **[时间轴数据量增长]** → 长期打卡后时间轴节点可能很多。**缓解**: 初期不分页，后续如有性能问题可加虚拟滚动或按月折叠。
- **[暗色→白色迁移]** → 全量样式重写工作量较大。**缓解**: 样式集中在 index.css 和 App.css 两个文件中，一次性替换风险可控。
