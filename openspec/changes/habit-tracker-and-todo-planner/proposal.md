## Why

当前应用只有基础的 Todo List 功能（增删改查），无法满足用户对"习惯培养"和"重要事项待办管理"的需求。用户希望拥有一个轻松无压力的习惯打卡系统——只关注累计天数，不做周/月/年对比——以及一个可排序、自动推算截止日期的待办事项管理器，已完成事项会保留并给予表扬，而非直接删除。现在是扩展应用功能的合适时机，因为现有架构（React + Vite + PWA + LocalStorage 持久化）已经稳定，可以在此基础上自然扩展。

## What Changes

- **新增习惯打卡模块**：用户可创建习惯（名称、寄语、开始时间、喜欢的颜色），当日一键打卡，以及通过日历界面对往期日期补卡；只展示累计打卡天数，不做任何周期性统计对比。
- **新增待办计划模块**：用户可创建待办事项（名称、预计完成时长），支持拖拽或手动排序来调整优先级，系统根据排序自动推算每项的截止日期；完成的事项标记灰显并移至底部或"已完成"界面，附带表扬反馈。
- **新增多页面路由**：引入页面路由以支持习惯打卡（当日打卡 + 新增习惯）、补卡日历、待办管理、已完成事项等界面的切换。
- **保留现有 Todo List 功能**：原有 Todo List 作为独立模块保留，不受影响。

## Capabilities

### New Capabilities
- `habit-tracking`: 习惯创建、当日打卡、日历补卡、累计统计的完整功能
- `todo-planner`: 待办事项创建、排序、自动截止日期推算、完成归档与表扬的完整功能
- `app-navigation`: 应用内多页面路由与导航结构

### Modified Capabilities
- `todo-list-app`: 需要在现有应用壳中集成新的导航与模块入口，应用结构从单页面扩展为多模块

## Impact

- **前端代码**：新增习惯打卡与待办计划的组件、页面、状态管理逻辑
- **路由**：引入 React Router 或类似方案实现页面切换
- **Local Storage**：新增习惯数据和待办计划数据的存储 key 与数据结构，需与现有 todo 数据隔离
- **PWA 缓存**：新增页面与资源需纳入 Service Worker 缓存策略
- **依赖**：可能新增 react-router-dom、日历组件库（或自行实现）、拖拽排序库等依赖
- **Garfish 集成**：子应用生命周期接口不变，但内部路由需适配 Garfish basename
